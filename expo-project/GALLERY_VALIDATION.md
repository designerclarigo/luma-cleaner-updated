# Gallery implementation and verification — 2026-10-21

Expo 57.0.30, React Native 0.86.3, React/React DOM 19.2.3, expo-media-library 57.0.5, Reanimated 4.5.1 and Worklets 0.10.1 are retained. Dependency declarations and the existing lockfile are unchanged. Splash, onboarding, theme tokens, fonts and approved navigation remain intact.

## Implemented and checked

- Real photos/videos load through SDK 57 `Query` and `Asset.getInfo`, with pagination, explicit permission requests, limited/denied states, original asset IDs and measured sizes where available. Loading/permission failures never select samples. Demo is a separately selected and persisted mode.
- Limited-access management now calls supported `presentPermissionsPicker`, replacing the obsolete `presentPermissionsPickerAsync` call. Live `addListener` subscriptions are removed on mode changes/unmount. Native change bursts coalesce; refresh pauses during review, pickers, backgrounding and system deletion prompts. Returning from Settings rechecks permission. Albums reload with the new catalog.
- A refresh keeps the active card while querying. Permission revocation clears the displayed originals. A stale query cannot put confirmed deleted items back into the catalog. Events arriving during a slow query schedule one subsequent refresh.
- SDK 57 dates stay in milliseconds; durations convert from native milliseconds to display seconds. Missing dates remain undated. Android numeric picker IDs resolve to original MediaStore content URIs, never temporary picker copies.
- Swipe/Keep acknowledgements reject stale or protected callbacks. A rejected exit animation returns the card to its original position. Undo, bookmark protection, save/reload, scoped device/demo state, interrupted-deletion reporting and keep-only completion are covered by regression tests.
- Review submits only selected, accessible, non-bookmarked device originals. Native confirmation is awaited. Cancellation leaves marks available. Only confirmed IDs count; unknown file sizes are excluded and reported separately. Results label the known size of removed media rather than claiming an immediate increase in device free space.
- Active and rear swipe cards explicitly use centered `contain`. Collections retain their existing thumbnail layout. Forest-green/ivory tokens and splash/onboarding source files were not changed.
- EAS development and preview profiles explicitly produce APKs. Development enables the development client; preview explicitly disables it and embeds the release bundle. Build scripts use pinned EAS CLI 25.2.0 without requiring a global installation.

## Android 10 confirmation limitation

The connected Redmi Note 7S runs Android 10. Expo Go 57.0.9 previously loaded Luma's Home screen on it, but lacks `ExpoMediaLibraryNext`; this does not test real gallery access. A new development or standalone preview APK is required for real media.

The installed SDK 57 Android implementation uses `AssetLegacyDeleter` below Android 11. That path directly deletes files and swallows individual deletion failures. Luma blocks it before importing/calling the native deletion API; review explains the limitation and disables Delete selected while Keep everything remains available. **Native confirmed deletion requires Android 11+ or iOS with this implementation.** Android 10 can still view/organize media in a native APK, but deletion must be performed in the system gallery. No filesystem fallback or simulated native confirmation was introduced.
